# Requirements policy

This project follows the super-repo's
[requirements policy](../../docs/policies/requirements_policy.md). Requirements and
test coverage are tracked exclusively through **little-requirements**
(`lreq` / `mcp__little-requirements__*`), against a project database at
`bundle-littles/req_db/little-meals_reqs.db` — never edited directly.

## Project-specific notes

- Wired into `bundle-littles/BUILD.bazel` as `setup_little_meals_env` /
  `//:req_sync_little_meals`, against `req_db/little-meals_reqs.db` (project id
  `little-meals-reqs`).
- Milestone 1 (`m1-recipe-ingestion` suite) created nine requirements,
  REQ-000000001 through REQ-000000009 — see `milestones.md` for the full list and
  the test files under `tests/` for what each one maps to.
- Requirement IDs are auto-generated by `little-requirements` in the fixed
  `REQ-#########` format (see the
  [root requirements policy](../../docs/policies/requirements_policy.md)) — they
  cannot be given a custom prefix like `MEALS-`. Once a milestone begins, create
  each requirement via `lreq` first to get its real ID before tagging tests.
- Test suite: `pytest` under `tests/`, tagging tests with
  `@pytest.mark.requirement("REQ-XXXXXXXXX")` to report results automatically.
  Reporting requires `little_requirements` importable and a `.reqs/` workspace in
  the repo root — regenerate it with `lreq workspace download --project-id
  little-meals-reqs --db-path <bundle-littles>/req_db/little-meals_reqs.db`.
  `.reqs/` is gitignored (it holds a machine-absolute DB path). Under `bazel test
  //...` the plugin is absent by design (it's a dev-time tool, not a `pip.parse`
  dependency — see `architecture.md`), so `tests/conftest.py` registers the
  `requirement` marker itself; the marker is valid either way, but only the plain
  `pytest` path (with `little_requirements` installed) reports results into the
  database.
- Known issue: `lreq update` (what the Bazel genrule invokes) cannot run inside
  this submodule checkout — `little-requirements`' managed pre-commit-hook
  installer assumes `.git` is a directory, and a submodule's `.git` is a file.
  Use `lreq workspace download` instead (as above), which doesn't install hooks
  and isn't affected.
